# Contributing

Keep changes small and include the user problem, screenshots for UI changes, and test evidence. Run `node --test tests/*.test.js`. No build step is required. Discuss new dependencies in an issue first.

Use fictional people, locations at city precision, and synthetic documents in tests. Never submit real GEDCOM files, family documents, passwords or addresses. Keep import adapters separate from the core model. Preserve keyboard navigation and reduced motion. Open an issue before implementing a roadmap subsystem so its data contracts can be agreed.
